# 0003. マッピング対象のデータソースにフォルダ内ファイルリストを採用する

- Status: Accepted
- Date: 2026-09-24

## Context
ルールベースの JSON マッピング機能で扱う入力データソースとして、フォルダ内ファイルリスト・地図 API・Spotify API・郵便番号 API を比較検討した（#10）。

## Decision
データソースはフォルダ内ファイルリストを採用する。

- 地図 API・Spotify API は API キー取得や OAuth 認証が必要で、実装コストが本来学びたいルールベースでのマッピング設計から逸れるため見送る
- 郵便番号 API は入力に対してすでに構造化された JSON が返るため、キーの付け替えに近くなり、ルールベースでの構造化を学ぶ練習としては物足りない
- フォルダ内ファイルリストはファイル名の表記に揺らぎがあり、正規表現やルールで解釈して JSON に構造化する必要があるため、次のステップ（自由入力の LLM 構造化）への橋渡しとして最も適している

## Consequences
- 実際の個人フォルダの内容を README やテストにそのまま使うと、ファイル名からプライベートな情報が漏れる可能性がある → `fixtures/` にダミーのファイル名・構成を用意し、実装・デモ・README の例示にはそちらを使う
- API 連携（認証・レートリミット対応など）の実装経験は今回は積めない
